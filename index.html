strategy.spec.js

describe('How I Structure Testing')

Coverage is not a number you chase — it is a shape. Drag the pyramid, or hover a layer to see where I put the effort and why.

Unit 60%
API 30%
E2E 10%
drag to rotate · hover a layer
E2E ~10% of effort
Few, slow, expensive to maintain — so they only cover journeys that lose money when they break: signup, checkout, core flow. Run before release, never on every commit.
SeleniumTestNGPage Object Model
API & Integration ~30% of effort
The best value per hour in QA. Endpoints validated against the requirement, not against a 200 — status codes, payload shape, error paths, and auth boundaries.
PostmanRESTSchema checks
Unit ~60% of effort
Developer-owned, and I read them. Where unit coverage is thin, the bugs I file get repetitive — so I point at the gap instead of re-catching the same defect by hand every sprint.
JUnitFlutter TestCoverage review
Exploratory continuous
Not a pyramid layer — a habit. No scripted suite finds the defect nobody thought to script. Timeboxed sessions against every release, notes and evidence captured as I go.
